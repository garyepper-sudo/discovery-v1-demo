## Implemented boundary

The seven-step Product loop—Set up, Prepare, Freeze, Capture, Review, What
changed, Prepare again—remains anchored by `ProductQuestion`.
`PreparedWorkProduct` is a versioned Product Workflow artifact, not cognition,
Evidence, authority, or a second Question. Freeze creates an immutable snapshot.

Capture registers or resolves the canonical local Source Binding, persists exact
bytes through Governed Source Content, and retains only the immutable content
receipt in Product Workflow. Server-derived typed proposals require explicit
human dispositions. Approved proposals then route through existing canonical
owners; approval itself grants no canonical authority.

## Actual-owner execution

Canonical server composition constructs authorization, repositories, adapters,
services, clock, and deterministic helpers internally. Semantic server actions
do not accept dependency objects or caller-supplied canonical identities,
receipts, revisions, or changed/unchanged classifications.

The router derives typed routing receipts only from actual owner results:

- Evidence consumes the exact operation-bound zero/one/many admission batch.
  Exact Class 2 duplicate Evidence skips cognition and leaves Organizational
  Understanding unchanged; material Evidence continues through cognition.
- Product Decision Draft consumes the persisted immutable draft receipt while
  the Executive Decision pipeline remains the sole actual Decision owner.
- Unknown and follow-up Question routing consume the actual canonical mutation
  or creation result.

Owner-specific results compose the truthful change projection and the next
Prepared Work Product reference. Generic Outcome routing and Decision promotion
remain deferred.

## Deterministic acceptance

The unified fresh-process acceptance uses temporary filesystem repositories:

1. Process A persists the real conversation context, preparation revisions,
   and frozen snapshot.
2. Process B reloads A and persists the real Source Binding, Source Content,
   upload receipt, proposals, and dispositions.
3. Process C reloads those exact artifacts, independently constructs canonical
   server composition, and routes the exact proposals through actual owners.

Idempotent re-entry creates no duplicate canonical or Product Workflow records.
Independent validators cover contract rejection, frontend non-disclosure,
authorization-before-read, root isolation, artifact tampering, replay, and
owner-result binding. Persisted artifacts and owner execution are joined by
deterministic identities and integrity-checked receipts rather than fixture
assertion or synthetic positive-path callbacks.
