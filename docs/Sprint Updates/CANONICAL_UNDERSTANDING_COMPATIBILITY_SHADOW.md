# Canonical Organizational Understanding Compatibility Shadow

## Decision

Discovery 2 Phase 4B is complete.

Classification:

```text
B — Category A requires minor compatibility refinement
```

The accepted Category A architecture remains valid. Canonical Organizational
Understanding can compose reusable truth through exact completed-Explanation
references without copying Explanation claims, ancestry, assumptions,
comparative Evidence roles, or role availability.

The benchmark does not authorize ownership migration. Existing executive and
application outputs remain derivable only through explicitly labeled legacy
read-through behavior. Bounded downstream derivation adapters must be proven
before the assessment-derived path can be replaced.

## Implemented shadow

`buildCanonicalUnderstandingCompatibilityShadow()` consumes completed
Explanations emitted by the normal:

```text
runDiscoveryV3()
→ evolveOrganizationRuntime()
```

path and constructs an ephemeral Category A composition containing only:

- deterministic composition identity;
- deterministic revision identity and previous-revision continuity;
- organization and governed scope;
- outcome composition;
- exact Explanation membership;
- composition-level unresolved-alternative and role-availability uncertainty;
- creation and update metadata.

The canonical candidate contains no copied Explanation claim, ancestry,
assumption, Evidence-role, or comparative-semantic field.

`resolveCanonicalUnderstandingTrace()` resolves the authoritative completed
Explanation objects by reference. The trace view is ephemeral and is not a
second owner.

## Benchmark result

Command:

```text
npm run benchmark:canonical-understanding-compatibility-shadow
```

Observed:

- 18/18 focused checks passed;
- 11 completed Explanations came from normal Runtime evolution;
- 17 reference-only Category A compositions were formed;
- real production Explanation input passed;
- Category A preservation and ownership separation passed;
- reference-based trace resolution passed;
- stable identity and revision continuity passed;
- organization isolation passed;
- the existing Atlas Runtime remained byte-identical;
- historical Understanding received no fabricated ancestry;
- a bounded non-executive consumer used Category A without Executive
  Assessment;
- repeated execution was byte-identical;
- no Runtime byte, field, schema, producer, or canonical output changed.

The gate classifies B because exact existing consumer behavior was preserved
through legacy read-through rather than derived from Category A plus each
consumer's proper contextual inputs.

## Rollback

Rollback removes:

- the pure Category A compatibility builder and trace resolver;
- the focused compatibility gate;
- this report;
- the package command.

The Runtime imports none of the shadow infrastructure. No persisted object,
schema, migration, or historical repair exists.

## Recommendation

Discovery 2 is not ready for the Phase 4 Canonical Ownership Migration sprint.

The smallest next evidence sprint should replace one legacy read-through at a
time with a pure bounded derivation adapter. It must begin with the current
Organizational Understanding compatibility view, then Executive Assessment,
before recommendation, communication, projection, or product adapters are
considered. No adapter may copy Explanation ownership or persist a parallel
truth object.
