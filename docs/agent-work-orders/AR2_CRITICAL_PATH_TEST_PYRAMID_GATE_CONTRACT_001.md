## Thresholds and failure rules

The inventory thresholds are normative:

- 100% mandatory commands PASS on exact candidate bytes;
- 100% required critical facts supported and owner-mapped;
- zero unsupported or duplicate/conflicting mappings;
- zero static, transformed, inferred, or profile-derived observations;
- zero trusted FAIL or BLOCKED results;
- zero unauthorized protected reads;
- zero disallowed duplicate canonical records;
- zero public scanner findings;
- zero task-owned external/local residue;
- zero new architecture findings, with exactly seven inherited findings allowed;
- zero package-lock drift absent a future separately approved contract.

Overall precedence is `BLOCKED > FAIL > PASS`.

Every evidence-producing command must pass twice consecutively against identical source bytes with identical normalized source, command/inventory, fact, result, and evidence identities. A mismatch is `BLOCKED — NONDETERMINISTIC TEST PYRAMID`, not a pass after retry.

Timing luck, arbitrary retry, broad timeout increase, order dependence, ambient state, previous-run residue, manual browser intervention, or inferred cleanup prevents freeze.
