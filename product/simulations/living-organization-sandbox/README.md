# Living Organization Sandbox Foundation

This Product-owned, non-Production simulation uses organization `sandbox-northstar-implementation-services-001`, a bounded company derived from Northstar material without modifying Northstar benchmark fixtures. Its primary Question is “Why are customer implementations taking longer?” The unrelated control area is community science volunteering.

The six ordered manifest batches contain company context, an incomplete operating picture, diagnostic comparisons, a policy constraint and counterevidence, future Outcome/Learning source material, and five negative controls. All files are Markdown, source-controlled, content-hashed, and loaded locally. No single source states a complete conclusion.

The replay calls the canonical organization-investigation orchestration, which owns Evidence production, cognition, Runtime evolution, persistence, and history. An exact eligible sandbox disclosure decision feeds the canonical Organizational Understanding projection compiler. Checkpoints contain bounded identities, counts, digests, uncertainty, contradiction, investigation, and evolution summaries; they never serialize raw Runtime or source text.

Reset owns exactly three artifacts beneath an explicitly named temporary sandbox root: the dedicated Runtime file, checkpoint file, and reset receipt. It rejects Production, the wrong organization, repository/shared paths, path aliases, and symbolic roots or owned subdirectories. It never mutates Drive content. Future sandbox-owned artifact classes must register exact filenames in the manifest rather than broaden deletion.

Commands:

- `npm run validate:living-organization-sandbox-manifest`
- `npm run living-organization-sandbox:reset`
- `npm run living-organization-sandbox:replay -- batch-2`
- `npm run living-organization-sandbox:replay-all`
- `npm run validate:living-organization-sandbox-foundation`

Commands default to an isolated temporary root. A persistent local root requires `--root=/tmp/discovery-living-organization-sandbox-<name>` and remains subject to the same fail-closed checks.

This foundation proves deterministic local corpus identity, bounded reset, canonical local replay, authorized projection, longitudinal checkpoints, negative controls, and exact cleanup. It does not validate Google Drive, organizational recommendation or decision integration, decision review/supersession, report snapshots, PDF export, final UI, autonomous action, or Production readiness. A later Drive task can map the same manifest document identities, versions, hashes, and batches onto the existing governed connector without changing acceptance semantics.
